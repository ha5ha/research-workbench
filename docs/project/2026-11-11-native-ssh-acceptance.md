# 原生 SSH 与生产桌面恢复验收

日期：2026-11-11。使用所有者授权的科研项目、服务器与原项目已有加密凭据。此轮实际调用 Electron 设置页、Main vault、分发 Core bundle 和 `ssh2` 适配器；不使用 Paramiko 作为任务传输。先前桥接验证见[历史记录](2026-11-11-real-ssh-validation.md)，本轮结构化证据见[native-ssh-20261111.json](evidence/native-ssh-20261111.json)。

## 实际结果

| 验收          | 结果                                                                                                             |
| ------------- | ---------------------------------------------------------------------------------------------------------------- |
| 原生密码设置  | 在隔离用户目录从密码框保存，保存后输入框为空；safeStorage 可用，重开后仍能认证                                   |
| 可信主机身份  | 无密码探测得到的指纹与所有者既有 `known_hosts` 匹配后，才在 UI 明确确认并认证                                    |
| 审阅与批准    | UI 审阅冻结命令、输入、预算与连接身份，一次“批准并运行”；同键重复调用返回同一 Job                                |
| 强杀生产 Core | Job 为 running 时 SIGKILL 精确的 bundled Core 子进程；关闭并重开 Electron 后仍看到同一 Job running，随后成功归档 |
| 关闭桌面      | 第二个独立 Job 在 running 时退出 Electron，重开后仍为原 Job running，最终成功                                    |
| 两轮重复      | 主指标差值 0；本地与远端逐源结果完全一致；120 项数值检查，最大绝对差 `1.7763568394002505e-15`                    |
| 取消          | 远端 supervisor 确认 canceled，本地状态一致                                                                      |
| 超时          | 1 秒预算下 failed/timeout，未冒充正常完成                                                                        |
| 缺件          | 退出 0 但缺少必需报告，保留 missing manifest 并判 failed                                                         |
| 凭据检查      | 最终复验扫描 204 份本地生成文件，未发现明文密码；测试不生成 trace 或密码输入截图                                 |

本轮正式验收目录只有 5 个 Job，全部到达终态，没有因重开/重复请求多提交。设置截图中的连接地址、账户与指纹均遮挡，见[截图与报告](../../design/implementation/native-ssh-20261111/)。

## 科研与写入边界

输入仍是已归档 T011 的三份预测汇总表，2016 行、6 个源模型、每源 336 项。复制时再次核对原项目文件与既有证据 SHA-256；运行独立 Python 标准库算术复核，不训练、不推理、不选择新参数，不修改原科研任务、代码或结果。

代码与输入冻结到新的本地维护工作区；服务器只在已授权工作空间下新的 `workbench-validation/native-real-*/job-*` 写入。每个 Job 时间、日志和必需产物都进入冻结方案。本轮不确认新科学结论，不把算术重算当作泛化或机制证据。

凭据辅助进程只把所有者已有 DPAPI 密文解密结果通过匿名管道交给验收进程内存，再填入原生密码框；密码不在 helper 源码、命令行、环境变量、fixture、报告、截图或模型上下文中。任务执行与回收均由产品 `ssh2` 完成。

## 失败记录与恢复

测试驱动首次误把 `preparing` 当作提交完成，提前退出。该隔离台账重开后正确保留 unknown；只读核对其专属远端根目录不存在，未产生远端 Job。修正驱动为等待 running 后才注入故障，重新在独立目录完成上述正式验收；没有把旧记录改写为成功。

本轮台账、快照、日志和原始输入保留在本机忽略目录，不进入 Git。清理前需核对精确目录、全部终态及产物引用；不删除原项目证据。回滚应用前退出 Core，备份 `.research` 与加密用户配置，核对 schema 和活动 Job；未知状态先核对，不能重新提交冒充恢复。

驱动：[verify-real-ssh.mjs](../../scripts/verify-real-ssh.mjs)。这是现场 opt-in 验收，需要原项目已有凭据连接和上一轮已验真的本地 provenance；不作为普通贡献者 CI。公开版本通过 `RW_QA_REMOTE_PYTHON` 和 `RW_QA_REMOTE_ROOT` 指定已授权的远端绝对路径，不保留个人服务器目录。它不证明 MFA、ProxyJump、真实 TCP 中断、长期 GPU 作业或任意服务器环境已通过。
