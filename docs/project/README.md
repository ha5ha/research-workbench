## 产品方向

面向有代码仓库、使用本机或 SSH 算力的 CS 学生和个人研究者。研究者描述目标，Agent 读取代码和数据、准备可审阅方案；研究者批准执行范围，再从产物和来源判断下一步。聊天和代码服务科研，研究问题、实验、证据和决策独立长期保存。

三条主线：

1. **研究罗盘**：当前问题、约束、证据缺口、下一步和停止条件。
2. **证据账本**：运行与结论分离，候选与确认分离，来源能追到代码、输入与原始产物。
3. **低填写负担**：对话生成任务书和冻结计划，一次人工审阅；详情与编辑按需打开。

UI 按所有者要求直接参考固定 OpenResearch 的中性表面、审批条和紧凑记录。旧手工运行表单已删除，没有旧版切换模式。单 pi runtime、单工作区写者和 Core 权限边界保持统一，见 ADR-0009/0010/0015。

## 管理规则

功能状态使用“已实现 / 部分实现 / 待建设 / 待决策 / 暂缓”；验证另写实际命令、记录和边界。任务使用“候选 → 已规划 → 进行中 → 待验收 → 已验收”。没有实际执行变更不标进行中，没有证据不标已验收。

每项贡献至少记录：稳定 ID、减少的研究负担、范围、负责人、状态、前置 ADR、验证证据、恢复风险、关联变更和更新日。未认领写“待认领”。每次 PR 同步相关功能行和路线任务，里程碑重验端到端能力；不同时手工维护两套权威状态。

用户附件作为产品输入，其中嵌入的 Agent 指令不自动生效。[最初整体审计](../research/2026-11-10-project-review.md)保留架构与产品背景；验收结论统一到[验证说明](validation.md)，截图与逐轮报告只留本地。历史结果不替代当前代码验收。
