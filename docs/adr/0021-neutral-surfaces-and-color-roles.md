# ADR-0021：统一中性表面与颜色职责

- 状态：Accepted
- 日期：2026-11-11
- 授权：所有者要求再次统一检查过多边框与冲突配色，沿用直接重构、OpenResearch 视觉方向与源码复用授权
- 关联：ADR-0009/0020、UI 合同

## 问题与约束

基础控件已共享，但页面仍遗留冷灰硬编码、蓝色协议/权限选中卡、彩色聊天卡竖条、逐项边框及嵌套指标框。它们来自不同实现阶段，增加科研信息的视觉噪声。

本轮只修改 `packages/ui` 的视觉 token、Renderer 页面样式与现有 CodeMirror 展示适配；不改变 Core/RPC、权限、运行或证据状态。目标是减少配置与读结果时的辨认成本。焦点、危险操作、失败/警告、运行状态、支持/反证与 diff 必须继续可辨认；不能把有语义的颜色全部抹掉。

## 决策

1. 白色、侧栏灰、轻灰 hover/selected 为普通表面；页面及编辑器不得自行写颜色字面量。警告背景/边框、遮罩、滚动条和 diff 色统一到现有 token 文件。
2. 协议、权限、SSH 连接的选中态采用中性背景和勾选/文字，不用蓝框或绿色“当前”暗示成功。蓝色保留可见键盘焦点和有目标的链接；红/琥珀/绿只表达具体语义。
3. 权限选项、设置概览、指标、空态与聊天卡内部优先用留白组织；独立输入区、菜单/对话框和需审阅的对象保留必要边界。去掉聊天卡的类型彩色竖条与研究详情的内嵌整框。
4. CodeEditor 与 SideBySideDiff 共用现有 CodeMirror theme 适配，字号与行高保持原值，diff 新增/删除保留低饱和语义背景。
5. 直接修改原有规则和组件，不在样式末尾叠加覆盖、不保留旧主题。升级/回退只涉及展示层，研究台账与产物不迁移。
6. 删除每条回答的协议旁注、重复设置导语与支持说明；输入区去掉“工作区执行”、重复附件说明和内部两条分隔线，有附件时才显示数量。配置字段、审批依据、错误和离线演示标识保留。

## 验证与退出

先保存真实 Electron 修改前基线。覆盖七类设置、对话菜单/权限、项目详情、代码、科研审阅与运行/结论，检查 1440×900、1024×768、390×844 及 200% 缩放；用真实计算样板验证状态、焦点、错误与保存恢复。异步驱动连续三轮，类型检查、lint 与相关截图/交互检查通过；做一次独立存量视觉评审，修正后由主代理复验。

最终版本连续三轮各通过 54 项控件/表面、21 项聊天检查及科研闭环/6 项视图检查；记录的源码和构建哈希与当前文件一致。类型检查、边界 lint、开发构建、许可收集通过；自有 Renderer/UI 色值集中到 token。独立存量视觉评审修正了冻结文件操作残留的蓝色，UX 走查过程与限制单独记录。

当前便携 EXE 不随开发构建自动重打。结果、截图、失败重跑记录与验收边界见[验收记录](../../design/implementation/surface-colors-20261111/README.md)和[机器核验](../../design/implementation/surface-colors-20261111/verification.json)。本轮未复测真实 provider/SSH 或便携 EXE。
