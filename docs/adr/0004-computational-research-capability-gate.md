# ADR-0004：计算科研能力门禁与 Research Skills

- 状态：Accepted
- 日期：2026-10-23
- 关联：[计算科研 Skills 体系](../research/computational-research-skills.md)、[代码工作面](0003-coding-surface-and-managed-runs.md)

## 背景

产品必须同时具备 Codex/DSH 级别的通用执行能力与科研特性。但“通用”不是无边界扩张：

- 如果只是编程 Agent，数据分析、结论整理、研究路线会继续由用户手工维护，越做越乱；
- 如果只做科研面板，缺少真实 coding/terminal/data 能力，实验无法落地；
- 如果照搬所有通用 Agent 产品能力，会偏离计算科研，增加维护面。

因此需要一个**能力门禁**：保留服务计算科研的通用能力，排除不服务该目标的产品面。

## 决策

1. 产品定位为**计算科研 Agent**：coding/chat 是执行底座，科研记录/分析/证据是产品核心。
2. 所有通用能力必须回答：**它是否减少研究者在代码、数据分析、结论整理或研究路线上的手工负担？**
3. 保留的通用能力（研究工具）：
   - workspace、文件读写/patch、diff、终端、测试、Git；
   - 会话、恢复、压缩/检查点、模型切换；
   - 权限/审批、MCP、Web、Skills；
   - 长任务与后台状态；
   - 子 Agent 仅用于独立检索/审阅等明确场景。
4. 暂缓/不做的产品面：
   - IDE 插件、PR review/issue 自动化、云端开发环境；
   - 多仓库/团队协作、应用部署、通用客服/销售连接器；
   - 与计算科研无关的通用浏览器自动化（Web 检索/抓取仍保留）；
   - 自动论文生成/投稿主张（后置，且必须以已接受 claim 为输入）。
5. 科研能力优先：
   - 研究路线/决策/证据/未决项的结构化沉淀；
   - 数据剖析、可复算分析、统计审查；
   - 任务书/受管运行/产物/复现；
   - 文献 ingest/检索/证据整理。
6. 科研能力以 **Research Skills** 交付，不以 prompt 代替：
   - 每个 skill 有输入、工具、确定性步骤、输出、审批、失败模式、评测；
   - 只能产生 proposal/artifact，不能自动确认 claim、批准 run 或删除证据；
   - 首版内置 research skills，不做第三方市场。
7. UI 继续遵循原型；Research Skills 通过输入框 `/`、状态页“研究路线”、记录/证据链接承接，不新增与原型冲突的顶级视觉概念。

## 不选择

- **纯 Codex fork**：缺少科研对象/证据/路线，用户仍要手工整理。
- **纯科研 Dashboard**：无法真正改代码、跑实验、分析数据。
- **无差别复刻通用 Agent**：把资源花在与计算科研无关的功能上。
- **把所有科研能力写成 system prompt/技能提示**：不可测试、不可审计、不可恢复。
- **自动论文流水线作为首版目标**：会诱导“生成看似完整的结论”，与本产品的证据边界冲突。

## 后果

- 正面：产品范围聚焦；通用能力有明确用途；科研层能真正减少整理成本。
- 成本：需要定义 skill contract、评测和 UI 承接；首版不能靠“通用功能数量”取胜。
- 风险：能力门禁可能误杀有价值的通用能力；每项排除必须有明确理由，可复议。
- 风险：科研 skill 变成“高级 prompt”；必须用确定性工具、artifact 和审批约束。

## 验收

- 一个真实计算研究任务从 coding 到数据/结论/路线完整跑通。
- 同一项目新会话能恢复路线、决策、证据和下一步。
- 数据分析和统计审查有可复算脚本/产物，不是模型口算。
- 每个 Research Skill 有 fixture 与失败用例。
- 不服务于计算科研的产品功能没有进入首版主线。
