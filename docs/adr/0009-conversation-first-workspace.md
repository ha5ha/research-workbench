# ADR-0009：以对话驱动科研工作区

- 状态：Accepted（2026-11-11，所有者明确要求直接借鉴 OpenResearch 样式与设计、直接重构，避免补丁与兼容层堆叠）
- 关联：ADR-0007/0008、UI 合同

## 问题与约束

任务书、运行配置、证据和决策集中为长表单，聊天已有的实验与运行提议却没有直接审阅入口。重复填写与重复确认破坏 Agent 主路径。本次用统一工作流替换旧 UI，而不是再增加一套模式；历史数据库和 Core 安全接口继续使用。

用户已指定参考，因此不另行评选视觉系统。借用主题数值与审批条的结构，归属及 MIT 文本见根 `THIRD_PARTY_NOTICES.md`。没有新增/升级生产依赖；第三方运行时和传递依赖不随此次适配引入。

## 决策

1. 对话为默认工作面。用户描述目标，Agent 读取项目、调用 `create_experiment` / `request_run`，完整运行提议由 Core 冻结。
2. 输入区上方持续展示权威台账中的待审计划；展开后显示任务目标、假设、命令、代码、预算、评测和外发范围。只保留一次“批准并运行”，仍执行 digest/快照校验和稳定幂等键。
3. 删除旧运行创建表单和旧任务书确认 UI，不保留切换旧版的兼容模式。实验记录创建改为次级“手工补录”，不伪装运行入口。
4. 罗盘成为阅读/审阅面：当前方向、下一步、计划、运行、证据与决策。方向编辑与人类决策只在请求时打开；运行和结论起草交给 Agent。
5. 运行详情复用同一组件，日志、哈希、事件按需展开；失败、缺件、unknown、取消可见。模型不获批准/确认能力。
6. 使用一个 overview 查询 hook，不复制 plan/run 状态进聊天持久化。结构卡只携带对象引用；刷新和切换会话后待审事项仍从 Core 恢复。

### 2026-11-11：审阅入口与冻结内容核对

独立真实 Electron 走查发现：已有待审方案时任务书仍突出“准备运行方案”；审批位置只能看到冻结文件名与哈希，不能核对代码语义。所有者要求直接完成这两处重构。

- 任务书卡与待审条共享同一 overview。动作由权威最新 plan、closure 与 run 投影：待审时直接审阅当前方案，撤回后显示原因并重新准备，替代后指向新方案，有 Run 后查看运行。不持久化第二套卡片审批状态。
- 复用现有 RunSnapshot、Core RPC 与 Main 白名单，增加 `plans.readFrozenFile {id,path}`；只接受该 plan manifest 的精确路径，只读取 `.research/plans/<id>/source`，核对完整大小与 SHA-256；绝不回退当前工作树。撤回/替代计划仍可只读回查，不重新开放批准。
- 审阅边界为完整 UTF-8 文本且不超过 128 KiB；拒绝二进制控制字符、非法 UTF-8、链接、越界、非 manifest 文件、缺失与篡改。拒绝时保留审批上下文、显示相邻错误与重试，不返回截断代码冒充完整审阅。
- 文件预览在现有抽屉内使用原生 button/pre，包含加载、错误、空文件、关闭与焦点恢复。复用 React/Electron 与现有 token，无新依赖。比较现有只读原生展示与已安装 CodeMirror：此次只需核对小型冻结文本，原生展示适配成本较低；CodeMirror 的编辑/语言服务能力已有独立 IDE 使用，不在审批抽屉重复装配。后续替换展示层不改变冻结读取契约。
- 验证包含工作树变化后仍读取冻结版本、内容/大小/路径/文本边界、关闭计划只读回查、撤回/替代的卡片状态、移动抽屉焦点与读取失败恢复。截图尊重 reduced-motion；字体以 CDP 实际平台渲染结果核对。
- 最终连续三轮真实 Electron 验收、边界测试与中英平台字体证据见 [修复验收](../../design/implementation/conversation-first-20261111/README.md)。

## 验证与退出

验证真实 Electron 的空状态、聊天提议/审阅、本地计算、结果、结论确认、决策、重载、失败草稿及三尺寸截图；现有冻结、安全、SSH 测试继续通过。UI 更新不改变数据库 schema 或执行器，可回退 renderer；回退前核对活动 Job，不删除台账/产物。原生 SSH 密码设置仍未交付，不能把此轮 UI 改造写成 SSH 完整验收。
