# 桌面科研 Agent 一站式工作台：产品方案 v0.2

日期：2026-10-20。基于用户明确选择桌面端、支持用户接入不同模型 API、参考 DeepSeek Harness（dsh）、pi 和 Codex 的通用执行能力，对 v0.1 重新定位。本文为设计提案，尚未实现；v0.1 保留为设计来源。

**产品定位：一个用户自选模型、在授权范围内操作本机和科研服务器，并持续维护研究问题、实验、数据、证据与决策的桌面科研 Agent 工作台。**

首批用户重点是计算机专业学生，以及使用代码、数据和本机或远端算力开展研究的个人与小团队。实验板块优先解决“Agent 能运行计算，并在完成后自动整理数据、分析结果、回到研究问题”的使用需要。研究问题、文献、证据与决策采用通用结构；自动执行和分析的首版覆盖计算型研究，人工实验作为可登记、可引用的外部步骤扩展。

科研管理、实际执行和成果阅读共用一个研究上下文：用户提出研究任务，Agent 调用工具推进，工作台展示过程与产物，并把它们连接到问题和证据。通用性先通过不同类型的计算研究验证，不以覆盖全部学科作为首版验收目标。

**一、桌面端的价值是连接研究资料、执行环境和长期研究记录。**

用户把本地项目目录、论文目录、数据位置和服务器接入一个研究空间，配置模型后即可讨论和执行。文件可留在原位置；系统为登记资料保存身份、来源和版本，必要时形成持久快照。选择材料目录和允许发送给外部模型的内容分别配置。桌面端本身不等于离线推理，云模型仍需调用相应 API。

任务由独立执行服务管理。关闭窗口后，已派发的远端任务按执行器能力继续运行；本机任务的后台继续、暂停及退出行为明确显示。电脑休眠或关机后，系统不承诺本机进程继续运行。重新打开时恢复运行身份和已保存状态，通信中断先查询已有任务，再决定是否重试。

**二、用户围绕子问题开展研究，Agent 在同一个工作台完成实际操作。**

典型请求是：“读这几篇论文，结合已有实验找出两个候选解释，设计能区分它们的对照；在这台服务器的预算内运行，结束后整理数据和未决点。”

Agent 查阅论文与项目记录，提出方案，按授权读写项目文件、生成或修改代码、运行检查、提交计算、登记产物、分析结果。工作台同步显示计划、文件差异、运行日志和证据。用户可随时修正方向、暂停执行或转为人工操作。

普通文件操作和命令保持通用 Agent 的灵活性。论文摘录、运行、证据及结论通过科研对象接口登记，使关键研究记录可校验和查询。探索阶段可以先操作再补充草案归属；已经冻结的实验条件和已接受证据使用版本记录。工作台持续显示待补充归属、缺失材料和待审核结论。

AI 的建议先作为候选方案、观察或解释保存。科学审核按照项目策略推进；引用旧结论需要保留适用范围。运行成功、产物完整、分析通过和问题解决各自显示状态。

结论卡先进入“候选”，证据齐全后进入“待审核”，由项目指定审核人按实验条件、分析覆盖、支持与反证及适用范围决定是否接受。新反证可使其进入“存在争议”，修订形成“已更正”版本；技术审核通过不自动代表解释成立。原始结果、观察和解释分别保留引用。系统沿依赖关系标出需要重新审阅的父结论、实验方案和决策，保留它们当时使用的依据。

运行交互按“提交 → 排队或运行 → 计算结束 → 产物可取 → 归档核验 → 分析与审核”呈现。用户可分别选择停止 Agent 后续操作、取消排队任务、请求终止计算；执行器确认后才更新实际计算状态。人工接管终端后记录操作与文件变化，恢复 Agent 时先核对现状再继续。计算结束后自动推进或等待负责人通知由项目策略确定；技术失败只有在确认原运行状态和符合重试授权后新建尝试，改变科学条件则创建新方案版本。

**三、一站式界面以研究对话为主，问题分支与证据始终可见。**

根据后续用户确认，布局调整为：左侧功能、问题分支与会话导航，中间默认研究对话并可切换代码等内容，右侧展示状态、证据与事实，底部可展开日志与任务队列。窄屏可折叠面板。当前 HTML 原型已按此布局更新，真实模型和执行能力仍待实现。

| 区域 | 内容 | 与科研记录的联系 |
| --- | --- | --- |
| 研究导航 | 项目、问题树、论文、实验、证据和决策 | 切换当前研究上下文 |
| 问题工作台 | 当前判断、假设、实验、发现、反证和下一步 | 作为每条研究分支的人类阅读入口 |
| 资料与文件标签 | PDF 阅读与摘录、Markdown、代码及差异、数据表、图表 | 对引用保存页码、记录键或内容版本 |
| 中央研究对话 | 对话、计划、工具操作、待决事项及执行摘要 | 对话绑定问题，可显式跨问题引用 |
| 右侧研究状态 | 任务状态、产物、证据、事实及当前上下文 | 展示当前依据、运行位置与待核验项 |
| 执行区 | 本机与远端终端、日志、任务队列、资源和成本 | 命令与产物关联具体运行身份 |

首版提供代码阅读、修改差异、终端、PDF 引用和 CSV/图表预览，复杂编辑可调用用户现有应用；逐步增加笔记本等能力。关键体验是从某条结论打开原始表、分析代码及运行，从某次实验返回它所验证的问题。

**四、底层借鉴通用 Agent，科研产品拥有独立的研究记录。**

| 参考项目 | 已核对能力 | 对本产品的设计启发 |
| --- | --- | --- |
| DeepSeek Harness | 权限预设组合沙箱模式与审批策略，两者仍独立执行 | 用户选择简洁模式，底层分别约束执行边界和审批 |
| Codex | 沙箱与审批分层；工作区执行及越界授权有明确边界 | 工作区内连续工作，越界时清楚展示具体请求 |
| pi | 提供 SDK、RPC、自定义模型及扩展工具调用拦截 | 可嵌入自有界面，把科研工具接到可替换的 Agent 运行层 |

依据：[dsh 权限预设文档](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/interaction/permission-presets/README.md)、[Codex 官方权限文档](https://developers.openai.com/codex/agent-approvals-security)、[pi SDK](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/docs/sdk.md)、[pi RPC](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/docs/rpc.md)、[pi 扩展](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/docs/extensions.md)。核对日期为 2026-10-20；参考能力不代表已选定其作为产品底座，三者也不具有完全相同的安全模型。

通用层负责模型调用、工具执行、会话、权限与恢复。科研层负责问题、假设、实验条件、运行尝试、证据来源、范围结论和决策。工作台负责阅读、操作与检查。无论更换模型还是运行框架，科研对象身份和来源链保持稳定。

立项后应选一个底座做嵌入验证，检查模型供应商接入、工具控制、长任务事件、恢复、许可及打包成本。首版只接入一个运行底座，预留适配接口；先验证其能否完成科研闭环，再扩大兼容范围。

**五、模型接入从首版支持用户自带 API。**

设置页包含供应商、API 地址、模型标识、凭据引用、可用参数和连接检查。常见兼容接口通过配置接入；存在协议或认证差异的供应商使用原生适配器。本地模型可通过本地服务适配，是否可离线使用取决于其能力和安装方式。密钥保存在系统凭据设施，不进入项目证据及普通日志。

模型能力检查分别展示文本、图像、工具调用、结构化输出和上下文等支持情况。只验证聊天连接不能证明该模型能够可靠执行多步任务；首版提供工具调用与结果返回的兼容检查，未验证能力明确显示。

默认由用户选择一个项目模型，也可为文献、代码或审核选择不同模型。首次版本优先手动选择；后续再加入按成本和能力路由。模型或供应商切换记录到任务历史，兼容层重建上下文并保留工具结果关联；无法继续时明确提示，不静默丢失记录或改变数据发送目标。

**六、权限采用熟悉的操作模式，科研授权随项目保存。**

建议提供“只读分析”“工作区执行”“完全访问”三类入口，并可展开目录、命令、网络和远端范围。模式名称是本产品建议，实际限制取决于执行器和平台能力。审批可按单次、任务或项目保存，范围变更和撤销记录可查，已授权范围内保持连续操作。

文件读取权限、内容发送给模型的权限、服务器操作范围分别显示。真正的执行限制需要运行层或操作系统落实；界面开关和提示词不能代替隔离。

科研层另存计算预算、实验条件版本、数据使用边界和结论审核策略。用户可以提前授权预算内自动执行和归档，避免逐条确认日常命令。完全访问决定执行器可以触达哪些资源，研究记录仍需如实标明证据状态、失败和更正。

**七、技术结构采用桌面界面、本地科研服务和可替换执行器。**

桌面界面负责研究导航、对话、文件预览、终端及授权。本地科研服务管理研究对象、会话、模型配置、任务、产物索引和事件。执行器负责本机、SSH 和后续调度系统；长时进程独立于一次模型调用。

建议首版使用本地结构化数据库保存元数据，文件系统保存产物或其登记引用。搜索索引从规范记录派生。授权范围内的团队同步后续加入，个人版可在不配置产品云端账户的情况下使用；外部模型和文献服务遵循其认证要求。

桌面壳选择根据团队经验与嵌入验证决定。无论采用何种壳，模型、运行底座、执行器、存储和科研业务接口分别定义边界。首版无需同时兼容多个壳或运行框架。

**八、第一版即提供一个小而完整的科研 Agent 闭环。**

第一版交付：桌面安装与项目目录接入、自带模型 API、基本权限模式、问题工作台、论文挂载与引用、Agent 文件和命令工具、本机及 SSH 运行、日志与产物登记、数据表预览、范围结论与决策记录、标准导出。

实验板块的第一优先级是“运行后自动沉淀”。每次运行绑定子问题、实验条件版本和尝试编号；登记实际代码版本或未提交差异快照、参数、输入数据身份、运行环境与输出位置。执行前约定输出清单和解析方式，完成后检查完整性，登记原始结果并运行可保存、可重跑的分析脚本，形成表图、现象说明、异常、支持与反证及未决点，再生成候选结论和下一步建议。失败或不完整运行保留真实状态；尚未支持的任意格式文件进入待解析列表，不能因 Agent 已写总结就显示归档完成。

接入已有脚本时，优先兼容命令行和文件输出，通过轻量结果清单、解析适配器或可选 SDK 登记数据。用户不必先把算法重写为平台专用框架。自动分析产生候选结果，结论是否被接受仍按项目策略判断。

首个演示使用已准备好的研究材料：用户选择一个子问题，Agent 阅读依据并提出有界实验，用户在项目范围授权后执行；运行完成后打开数据、生成分析、登记支持与反证，再提出下一步。探索和确认阶段由项目策略区分。

后续增加论文智能发现、专业统计模板、更多调度执行器、模型路由、多 Agent 协作和团队知识共享。完整笔记本环境、覆盖全部学科及大型插件市场在需求验证后扩展。

验收至少覆盖两个领域差异明显的计算型样例，包含成功、失败重试、负结果和历史证据复用。每次运行可追到实际代码、输入、配置及产物；每条已接受结论可追到文献或分析；更换模型不改变研究记录；断线重连不重复提交已有任务。科学指标和复现容差由各实验确定。

**九、现有项目用作首个适配样例，下一步先验证核心交互。**

保留现有目录和已完成记录，先只读映射问题、计划、运行、事实和证据。当前课题的统计规则、计算授权及完成通知方式进入项目配置。通用产品以独立包或独立仓库形成工程边界，避免把课题专用代码变成全局业务逻辑。

下一份可评审交付应是桌面工作台交互原型与核心对象协议：展示问题导航、Agent 面板、论文引用、文件差异、运行日志及结论下钻，并用一条历史研究分支验证它们是否能连起来。随后选择一个运行底座完成嵌入测试，确定实际开发技术栈。

**十、项目使用经验必须能够追到具体产品要求。**

本方案已经吸收了问题驱动、范围结论、证据追溯、失败尝试、远端恢复和项目策略等经验；此前对经验来源、条件差异、论文实现身份、分析可读性和多份记录维护成本的对应说明仍不充分。详见 [项目经验到产品要求映射](project_experience_to_product_requirements_v0_1.md)。该文区分仓库中有记录的实际问题、已有处理经验、v0.2 覆盖程度和建议新增机制；这些记录支持设计取舍，不表示桌面产品已经实现。

首版据此重点验收：换会话仍能找回当前问题和下一步；计算结束后完整归档并给出可重算分析；条件不同的结果明确标注可比范围；更正结论后能找到受影响的引用；用户从任何结论回到原始数据与实际运行。领域专用统计及输入规则通过项目配置和适配器提供，不写死当前课题的模型、数据集或方法。

**十一、项目记忆与模型上下文独立管理。**

2026-10-21 补充：跨窗口共享项目规则、版本化状态和有范围的事实；各会话保留自己的检查点与近期讨论。每次调用按当前问题、任务、预算和权限重新组装上下文。长会话自动生成检查点，原文与证据保留可查；压缩不能升级事实、改变任务状态或扩大执行授权。

完整机制、界面和验收要求见 [跨会话记忆与上下文管理设计](context_memory_design_v0_1.md)。本项为产品设计补充，尚未接入当前 HTML 原型。
