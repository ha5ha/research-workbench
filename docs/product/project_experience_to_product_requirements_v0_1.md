# 从当前项目的实际使用问题到产品要求

> 迁移说明：本文中的 `../../research/...` 链接指向原始科研工作区中的历史记录，不随本产品仓库分发，仅用于设计溯源，不参与构建或运行。

日期：2026-10-20。配套主方案：[桌面科研 Agent v0.2](research_agent_desktop_proposal_v0_2.md)。

这份记录回答两个问题：已有方案究竟吸收了哪些真实经验，实验板块应如何帮助计算机学生把运行结果沉淀为可用知识。材料来自本仓库现有工作流、决策、更正及维护记录；这里核对需求来源，不重新验算科学结论，也不代表桌面产品已实现。尚未进行跨项目用户访谈，以下经验的普遍程度仍需后续验证。

## 1. 已经吸收了一部分，经验来源和关键交互还需要补齐

v0.2 已明确问题导航、运行尝试、证据来源、结论范围、失败保留、远端恢复与可配置项目策略。这些对应本项目已经形成的处理经验。此前仍缺少“实际发生了什么 → 怎样处理 → 产品具体承担什么”的逐项映射，尤其是可比条件、方法实现身份、分析质量和维护成本。以下“覆盖”只指本次补充前的方案文字覆盖，不表示能力已经开发。

| 编号 | 仓库中有记录的实际问题 | 本项目形成的经验 | 原 v0.2 覆盖与产品要求 |
| --- | --- | --- | --- |
| P01 | 研究入口曾把一个目标当作唯一主问题，旧阶段队列与后来明确的研究主线不一致；旧入口还可能误导后续计算。[S01][S02] | 当前问题、已批准任务和下一动作由明确入口决定；旧轮次只供溯源。 | 部分覆盖。问题页保存当前判断、待答分支、已批准动作及决策理由；换会话或模型时从这些记录恢复。默认展示当前有效版本，历史检索注明版本与适用范围。 |
| P02 | 远端进程已经结束时，仍有本地同步和独立结果验收未完成；进程状态不能代表结果已归档。[S03] | 计算结束、产物完整、归档核验、分析及结论接受分别记录。 | 已表达，需落成交互。实验卡展示各阶段与缺项；按授权自动收集、检查、分析并回到问题。归档策略可选择本地副本或受管理的远端持久存储，不能把当前项目的本地镜像要求写死为所有项目的规则。 |
| P03 | 一次启动因两份输入说明字段名不同而失败，记录说明其语义等价，但执行器直接比较字典；失败尝试没有产生科学结果。[S04] | 技术失败保留原尝试，修复后新建尝试；合同表示和实际含义需分开核对。 | 失败保留已表达，语义适配缺失。运行前检查环境、路径和输入说明；适配器用显式版本映射统一字段并验证含义，保留原件。不能仅凭字段别名自动假定等价。 |
| P04 | 同名操作在不同输入归一化和采样条件下实际改变不同内容；两次实验也可能同时改变批次、状态更新与累计路径。[S05] | 结果必须绑定实际条件；跨条件差异不能冒充单变量因果。 | 部分覆盖。比较页自动并列代码、配置、输入、数据划分和状态协议差异；先按配置规则分组，再呈现匹配对照。自动标注只说明已登记条件，未记录差异保持未知。 |
| P05 | 方法简称无法说明项目实现是否忠实于原论文；能得到数值、实现正确和公平比较是不同验收。[S06] | 分开保存论文依据、作者实现、项目改动与实现身份；变体结果不改名冒充原方法。 | 文献挂载已覆盖，实现身份缺失。增加方法实现卡，关联文献段落、代码版本及改动；表中显示原流程核对、任务适配、变体或未决，并分别记录三类验收。 |
| P06 | 项目明确要求检查逐模型、逐重复及逐样本异常，不能仅用汇总均值解释；部分成功输出也不能当作完整实验。[S07] | 先核对统计单位和覆盖，再计算配对指标、分组汇总、波动及异常。 | 部分覆盖。输出清单登记预期条件与覆盖；保存原始明细和可重跑的分析脚本。计算型分析适配器提供可配置的分组、基线、重复和缺失规则，失败缺项显示原状，不补零。 |
| P07 | 负责人实际指出报告术语多、数值零散，缺少围绕问题展开的推理；项目随后修订了多份阅读文档。[S07][S08] | 报告先讲主要现象，再讲关键对照、例外、原因证据以及未解释部分。 | 仅有分析入口，表达要求不足。实验分析页先回答原问题，再展示关键表图、解释边界及可区分解释的下一步；提供明细下钻，不能只生成一段流畅总结。 |
| P08 | 历史摘要出现过错误基线，事实库保留了更正；后续机制说明也需要区分不同基线、参数和适用条件。[S09][S10] | 观察、解释、有限范围事实分别保存；更正保留旧版本及来源。 | 已表达，需落实引用行为。新分析先生成观察与候选结论；知识池保留支持、反证、未决和范围。引用时显示条件，更正后标记受影响的结论与决策等待复核。 |
| P09 | 本地历史目录和结果存在重复，部分目录含唯一证据；远端磁盘也曾接近满载，缓存名称不代表可以删除。[S03][S11] | 内容哈希、引用关系和保留来源先核对，再处理冗余或授权丢弃的产物。 | 内容登记已表达，存储维护不足。一个产物可被多个子问题引用，复用不创建新实验；首版显示位置、可用性、完整性和占用。后续加入存储策略，区分可再生成、已备份、唯一证据与用户明确授权丢弃，清理需有具体范围和记录。 |
| P10 | 旧 runner、配置和跨模块导入仍被历史复现引用；直接移动或修改会影响证据，旧默认参数又可能污染新任务。[S02][S12] | 冻结来源通过明确适配边界复用，活动任务配置独立；文件整理不等于数值等价。 | 代码版本已表达，执行隔离不足。运行绑定已提交版本或未提交差异、依赖环境和解析后的实际配置；历史重放使用原身份，新改动形成新版本。支持已有脚本，避免强迫迁移为专用算法框架。 |

这些问题共同指向一个产品要求：让系统保存并连接研究过程中的关键对象，减少用户维护多份状态、索引和报告的负担。本项目目前通过文件结构、合同和校验脚本维持这些关系；产品建议以规范记录生成问题页、比较页和报告。运行、重分析和展示报告分别保存身份：重算旧数据不是新实验，修改报告不覆盖旧分析或原始结果。导入已有项目时保留原文件及来源，外部修改需要检测并提示冲突，不能用自动生成的视图覆盖用户记录。

## 2. 实验板块先为计算机学生完成一条实用闭环

首批服务需要运行代码、训练或评估模型、做算法比较和消融实验的计算机学生，以及有类似计算流程的研究者。用户应能带着自己的仓库、命令、数据与服务器接入。研究问题、文献和证据结构保持通用，实验解析、指标含义及统计规则由适配器或项目配置补充。

一个子问题下面可以有多份实验方案，每份方案有若干次运行尝试，每次尝试登记输入、代码、输出及分析。一个结果可被多个问题引用，但来源运行保持唯一。方案、运行、分析、结论和问题状态分别保存，避免“运行成功”自动关闭问题。

| 步骤 | 用户在工作台看到什么 | Agent 自动完成什么 | 必须保留的边界 |
| --- | --- | --- | --- |
| 讨论问题 | 当前问题、已有证据、候选解释和未知 | 读论文与已有结果，提出能区分解释的实验 | 不把论文观点、历史观察或自己的推测直接写成已证实事实 |
| 准备实验 | 代码差异、实验条件、对照、指标、预期产物、资源和预算 | 生成或修改脚本，进行环境与输入检查，按项目策略提交 | 探索可以轻量推进；确认实验保留事先确定的条件和判断规则 |
| 实际运行 | 本机或服务器位置、运行编号、日志和真实状态 | 派发、保存凭据、采集运行信息；断线后核对已有任务再恢复 | 自动接续须在既有授权内；重试保留原尝试，不盲目重复提交 |
| 归档数据 | 原始文件、数据覆盖、缺项、保存位置与来源 | 检查预期产物、登记内容身份和来源，解析支持的结果格式 | 数据可按策略留远端或下载；不完整输出不能标为完整归档 |
| 分析结果 | 关键对照表图、现象、异常、解释与未决 | 保存并运行分析脚本，按匹配条件比较，生成可追溯报告 | 统计规则、匹配键和覆盖要显式保存，不静默取交集；任意日志和未知文件格式不能承诺自动理解正确 |
| 沉淀知识 | 候选结论、支持/反证、适用范围、下一步 | 将数据和分析连接到子问题，提出结论及下一实验草案 | 接受结论按项目策略；自动总结不代表机制证明或新计算授权 |

“跑完自动沉淀”在首版的完成标准是：运行条件与产物可追溯，支持的结果已经解析，所需分析已运行并保存，问题页能看到有边界的发现或明确失败原因。无法解析、材料缺失或分析失败时显示待处理项，保留产物供用户补充。自动化承担整理和推进工作，研究者仍能查看、修改、接管与审核。

关键异常也作为可追踪记录保存，包含比较范围、候选解释、支持与反证，以及能区分解释的下一实验。软件结构检查、数值复算、比较公平性及科学解释分别显示，不能因某一项通过就自动关闭异常或接受结论。

接入方式先兼容命令行和文件输出：使用轻量结果清单、解析适配器，按需提供 SDK。用户不必重写算法。CSV、JSON 和常用日志可作为首批格式；图片、模型权重和大数据保存引用及元数据，是否读取内容、下载或发送给模型分别遵循配置。具体格式范围在实现前以样例验证，不能由“Agent 可以读文件”推导为全部格式都已支持。

## 3. 哪些经验固化为通用能力，哪些留在项目配置

通用核心保存问题、假设、文献、方法实现、实验方案、运行尝试、产物、分析、结论和决策，以及它们的版本和引用。它负责实际操作可追溯、恢复时不重复提交、失败及更正不丢失、记录可导出。

计算型研究模块处理本机或 SSH 执行、日志、资源、数据解析、参数与指标比较。具体模型、指标方向、样本单位、数据划分、重复规则、参数选择限制、独立验收和完成通知方式进入项目配置。当前 EF 课题的专用方法、主干网络、VAL/TEST 及统计细节都不是产品全局默认。

首版优先实现 P01、P02、P04、P06、P07、P08 的最小闭环，并把 P03 的失败保留、P05 的实现身份和 P10 的实际代码/配置记录并入运行对象。P09 首版提供归档引用与占用可见性，完整迁移和自动清理以后再做。成熟通用 Agent 的权限、工具与会话能力通过运行底座复用，产品开发重点放在科研过程与产物沉淀。

## 4. 用历史分支检验设计是否真的减少使用负担

原型阶段用一条已有研究分支回放以下场景，不启动新的科学计算：

1. 用户重新打开或更换模型，问题页仍能说明当前在研究什么、已有何种证据、什么未决以及为什么选择下一步。
2. 同一实验保留失败与成功尝试；模拟重连后仍关联原运行，不把重试或复用当作独立复现。
3. 从一张比较表展开两次运行的实际条件差异，能看到哪些对照成立、哪些解释还不能支持。
4. 从一条结论返回分析脚本、原始数据、代码与配置，再返回它要回答的子问题。
5. 修订一条结论时保留旧依据，列出需要复核的引用；同一产物被另一问题引用时不重复复制原始数据。
6. 阅读分析首页就能知道主要发现、关键对照、异常及未解释部分；未完成的解析或归档在页面明确显示。

后续用本项目之外的一种计算型研究检验对象与适配边界，再开展实际用户试用。以上是待验证的产品验收场景，本次没有把它们标为通过。
