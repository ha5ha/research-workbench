# 轻量 UX 走查

日期：2026-11-11。环境：独立真实 Electron 测试窗口；隔离 fixture 项目、本地 fixture 模型。桌面 1440×900，补查同一路径的 390×844 方案审阅。只依据页面与实际操作，未读源码、设计说明、历史评审或预期测试路径。

## 产品理解与自选任务

首屏让我理解这是供研究者使用的项目型 Research Agent：从对话提出问题，Agent 帮忙理解项目和准备实验，研究罗盘与实验记录承接后续工作。

我选择的主要任务是：从首页让 Agent 准备一个小型 baseline 实验，找到生成的运行方案，审阅执行位置、输入和预算，确定下一步。**完成准备并进入审阅**；没有批准运行。本次没有遇到使这条路径完全走不下去的障碍，但审阅冻结代码的能力仍受限。

## 关键问题

### 1. 冻结文件无法在审批位置查看内容（犹豫）

**观察到的事实：** 展开冻结文件后，只显示 experiment.cjs 与哈希；点击文件名没有打开文件内容。抽屉底部说明“仅批准此代码、命令、输入和预算”，但本页实际可直接核对的是命令、输入、预算和代码身份，代码语义没有可见入口。[证据](ux-09-desktop-expanded-plan.png)

**原因推断：** 哈希能标识版本，却不能帮助研究者判断脚本执行哪些读写、如何计算指标。用户可能需要离开审批流程寻找代码，还要自行确认看到的内容是否就是冻结版本。本次未验证 IDE 中是否另有可关联的冻结版本入口，因此不把“全产品无法查看代码”作为结论。

**建议达到的结果：** 在此处能打开只读的冻结脚本或明确链接到同一冻结版本，让批准对象可以直接核对；返回后保留审阅上下文。

### 2. 方案已准备时，任务书仍把“准备运行方案”作为主动作（犹豫）

**观察到的事实：** 同一对话中，Agent 已回复“方案已准备”，下方固定栏也显示“运行方案已准备 / 审阅方案”；但更靠上的任务书仍显示“草案”和黑色“让 Agent 准备运行方案”按钮。我需要比较这两处，才选择下方的审阅入口。[证据](ux-10-prepared-state.png)

**原因推断：** 任务书动作没有清楚反映已有待审阅方案的状态，两个阶段的动作同时竞争注意力。这次没有点第二次准备按钮，所以未验证是否会重复生成方案，不声称已经发生重复执行。

**建议达到的结果：** 有待审阅方案时，任务书能标明该状态并直接进入现有方案；若保留重新准备，应明确它会生成新版本，使研究者不用猜哪一个才是当前下一步。
