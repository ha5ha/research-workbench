## 产品理解、自选任务与结果

从首屏理解，这是供研究者从对话准备和执行实验，再用研究罗盘保存结果与结论的工作台。首页的“准备一个实验”提供了清楚的起点。

自选任务：准备一个可复算 baseline，审阅其冻结内容，批准本地运行并查看结果。随后沿界面给出的入口继续生成、查看并确认样板结论。

**主路径已完成。** 可观察结果包括任务书、冻结文件只读预览、本地运行“已验证”、指标、已校验产物，以及从“候选”变为“已确认”的结论。来源原文核对遇到一处障碍，详见下文。所有请求和运行均为一次性本地确定性样板；这只验证界面路径与反馈，不能验收真实模型或科学有效性。

## 关键问题（1 条）

### 核验候选结论时，来源入口没有带到原始内容

**观察到的事实：** 在研究罗盘看到一条候选和“支持 · results/metrics.json”。点击来源后，没有出现文件内容或新预览，页面仍为同一运行详情。随后展开“results/metrics.json 43 B · 已校验”，只显示 SHA-256，未出现原始数据及查看内容按钮。此前冻结脚本可以通过“查看内容”直接核对，但运行产物没有同等入口。详见 [15](15-claim-source-after.png) 和 [16](16-artifact-expanded.png)。

**节点：犹豫 / 局部卡住。** 系统要求“核验证据后确认”，但在这条可见路径里只能核对归属、指标摘要和校验状态，无法直接查看所引用 JSON 的内容。主运行路径可继续，证据内容的人工核验在此受阻。

**原因推断：** 来源动作可能只定位所属运行，而产物折叠区仅承担完整性摘要。此为根据界面行为的推断，未读实现；也未断言其他未测入口不存在。

**建议达到的结果：** 点击结论来源后直接看到所引用产物的只读内容，或能从明确的预览入口继续；保留运行归属和哈希，使人在确认结论前能核对原始记录。
