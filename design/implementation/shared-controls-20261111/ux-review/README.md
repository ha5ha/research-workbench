## 产品理解与选择的任务

首页的“今天想研究什么”“准备一个实验”，以及“研究罗盘 / 实验记录”，让我把它理解为供研究者使用的桌面研究助手：从项目对话准备可执行实验，由人审阅后运行，再把结果和结论留在项目里。

我自主选择的主要任务是：**准备并运行一个 baseline 实验，查看产物，再核对一条结果结论。** 最初从“准备一个实验”进入，看到运行结果中的“让 Agent 分析结果”后继续走到结论。

结果：**部分完成。** 冻结方案已审阅、本机运行成功，界面显示“已验证”，并显示 score=4、n=2、sd=1.41421；Agent 创建了带来源的候选结论。原始产物内容未能在所走路径中直接打开。测试时点击“核验证据并确认”后，候选立即变成“已确认”，没有进入我预期的证据核对界面。

真实页面入口为本仓库开发构建的 Electron renderer（`apps/desktop/out/renderer/index.html`）。以下均为该窗口内的真实 UI 操作；没有用程序接口创建研究记录。本机专用驱动不随 Git 分发。

## 关键问题

### 1. 原始证据核对没有在结果与结论路径中完成 — 卡住 / 走错

**观察到的事实：** 运行详情把 `results/metrics.json` 展示为可展开条目，但展开内容只有未标注的 64 位字符串；没有展示 JSON 内容或打开/下载按钮。[13-artifact-expanded.png](13-artifact-expanded.png) 中可直接看到这一状态。候选结论上的“支持 · results/metrics.json”仍打开运行详情，[19-evidence-linked-run.png](19-evidence-linked-run.png)；没有定位到原始文件内容。随后点击“核验证据并确认”，结论直接由“候选”变成“已确认”，没有出现证据审阅步骤，[21-confirmed-claim.png](21-confirmed-claim.png)。

**原因推断：** 校验结果、文件内容核对和结论确认这几件事，在当前入口的文案与目标之间没有清楚区分。展开产物的交互让我预期能读到内容，“核验证据并确认”又让我预期先核对证据。我无法仅凭这一条真实路径确认是否存在其他原始产物入口，因此不把“整个产品无法打开文件”作为事实。

**建议达到的结果：** 从产物条目和结论来源都能直接读取该原始文件，看到两个种子的数值及相关运行；校验字符串有清楚标签。执行确认的按钮应明确说明会立即改变结论状态，让人能先阅读证据再决定确认。

### 2. “查看运行”先到总览，需要重新选择刚完成的实验 — 犹豫

**观察到的事实：** 实验卡片显示“已验证”及“查看运行”。点击后选中“研究罗盘”，页面展示“当前方向 / 实验与运行 / 证据与结论 / 研究决策”的总览；运行详情没有展开。[09-run-detail.png](09-run-detail.png) 记录该落点。必须再次点击其中唯一一条实验记录，才出现带指标与产物的运行详情，[11-result-loaded.png](11-result-loaded.png)。

**原因推断：** 按钮文案表达的是查看这次运行，但目标是工作区总览。一次实验时还可推断下一步；多条实验时，需要再次辨认所选运行。后一情形本轮没有验证。

**建议达到的结果：** “查看运行”直接展开对应运行的详情，并把焦点或可视位置带到结果；若保留总览落点，入口应准确表达目标。

## 反馈、恢复与未验证范围

已观察到的反馈：发送后出现处理状态与停止按钮；批准按钮附近出现“正在启动…”；运行详情读取时显示“正在读取运行…”；运行完成及结论确认有状态文字变化。审阅抽屉与权限弹层均能用 Escape 关闭并恢复触发按钮焦点。

没有验证真实模型质量、真实网络、SSH、凭据、导出、失败运行、权限拒绝、停止运行、多个实验之间切换、1024×768、屏幕阅读器、声音、触觉和真机手感。390×844 只检查了对话及权限弹层；继续进入窄屏罗盘时 CDP 报告 `Target page, context or browser has been closed`，故未完成窄屏结果页检查。这是环境结束，不作为产品缺陷。

测试只影响本次临时研究项目。最后测试结论状态为“已确认”；未编辑代码、未进行真实网络或 SSH 操作。没有主动关闭 Electron。会话在补查末尾已断开，主代理可按自己的隔离会话流程清理。

本报告不代表真实用户的成功率、满意度或操作耗时，也没有作审美评分。截图来自实际页面；`04`、`07`、`10`、`16`、`18`、`20` 包含操作后即时过渡状态，最终判断使用对应的稳定截图。
